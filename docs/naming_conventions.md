## **General Principles**

- **Naming Conventions**: Use snake_case, with lowercase letters and underscores (`_`) to separate words, for zones, folders, files, tables and columns. Synapse security and connection objects (credentials, data sources, file formats) use PascalCase.
- **Language**: Use English for all names.
- **Avoid Reserved Words**: Do not use SQL reserved words as object names.
- **Entity Names**: Use the same `<entity>` name everywhere a dataset appears (folder, file, external table, staging table), e.g. `sales_transactions`.

## **Zone Naming Conventions**

- Each zone is a separate **container** (file system) in the ADLS Gen2 account, so access can be granted per zone.

| Zone | Container | Medallion tier | Contents | Format |
|------|-----------|----------------|----------|--------|
| Raw | `raw` | Bronze | Source data exactly as received (ADF landing area) | CSV, JSON |
| Processed | `processed` | Silver | Cleaned, deduplicated, typed data written by Databricks | Parquet |
| Curated | `curated` | Gold | Reporting-ready aggregates and dimensional data | Parquet |

- Storage URL pattern: **`https://<storageaccount>.dfs.core.windows.net/<zone>/`**
  - Example: `https://datalakeproject.dfs.core.windows.net/processed/`

## **Folder Naming Conventions**

- **`<zone>/<entity>/`** for every dataset; one folder per entity, named after the entity in the source system.
- In the raw zone, each delivery goes into a Hive-style partition folder named after the load date, so Spark and `OPENROWSET` can prune and filter by partition:
- **`raw/<entity>/load_date=<YYYY-MM-DD>/`**
  - `<entity>`: Dataset name in snake_case (e.g., `sales_transactions`, `customer_logs`).
  - `<YYYY-MM-DD>`: Date the file was ingested, not the business date of its records.
  - Example: `raw/sales_transactions/load_date=2024-01-06/`
- In the processed and curated zones, Spark owns the folder content: **`<zone>/<entity>/`** contains the Parquet part files (and partition folders, if any) written by the job.
  - Example: `processed/sales_transactions/` → `LOCATION` of `ext.sales_transactions`.

## **File Naming Conventions**

- **Raw zone**: **`<entity>_<YYYYMMDD>.<extension>`**
  - `<YYYYMMDD>`: Load date, matching the `load_date=` folder.
  - `<extension>`: Lowercase format extension (`csv`, `json`).
  - Example: `sales_transactions_20240106.csv`
  - CSV files are UTF-8, comma-separated, with a header row. JSON files are JSON Lines (one object per line).
- **Processed / Curated zones**: File names are generated by Spark (`part-*.snappy.parquet`) and are never referenced directly; always address the folder.

## **External Object Naming Conventions**

### **Credentials, Data Sources and File Formats**

| Object | Pattern | Example(s) |
|--------|---------|------------|
| Database scoped credential | `<Store>Credential` | `ADLSCredential` |
| External data source | `<Zone><Store>` (one per zone container) | `RawADLS`, `ProcessedADLS`, `CuratedADLS` |
| External file format | `<Format>Format` | `ParquetFormat`, `CsvFormat` |

### **External Tables**

- All external tables live in the **`ext`** schema and are named after the entity folder they point to.
- **`ext.<entity>`**
  - `<entity>`: Name of the folder in the zone (e.g., `sales_transactions`).
  - Example: `ext.sales_transactions` → `ProcessedADLS` + `LOCATION = 'sales_transactions/'`.
- External tables point at the **processed** zone by default. If a table over another zone is needed, suffix the zone: **`ext.<entity>_<zone>`** (e.g., `ext.sales_transactions_raw`).

## **Synapse Table Naming Conventions**

- Tables materialized in the dedicated SQL pool use the `dbo` schema and start with a category prefix.
- **`<category>_<entity>`**

| Pattern | Meaning | Example(s) |
|---------|---------|------------|
| `stg_` | Staging table loaded from an external table | `stg_sales` |
| `fact_` | Fact table | `fact_sales` |
| `dim_` | Dimension table | `dim_product` |
| `<grain>_<entity>_summary` | Pre-aggregated reporting table at the stated grain | `daily_sales_summary` |
| `etl_` | Pipeline control/metadata table | `etl_watermark` |

## **Column Naming Conventions**

- **Business keys** end in `_id` and keep the source name: `transaction_id`, `customer_id`, `product_id`, `log_id`.
- **Dates** end in `_date` (`DATE`); **timestamps** end in `_timestamp` for business events (`event_timestamp`) or `_at` for technical events (`loaded_at`, `updated_at`).
- **Technical columns**: `loaded_at` is the time the row was written to the processed zone. It is added by Databricks, carried into `dbo.stg_sales`, and used as the incremental load watermark.
- **Measures** describe what is measured: `quantity`, `unit_price`, `total_revenue`, `transaction_count`.

## **Script Naming Conventions**

- SQL scripts in `sql/` are numbered in execution order: **`<NN>_<verb>_<object>.sql`**
  - Example: `01_create_external_tables.sql`, `05_incremental_load.sql`.
- Quality checks live in `tests/` and start with `quality_checks`: `tests/quality_checks.sql`.
